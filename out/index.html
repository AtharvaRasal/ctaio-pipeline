Claude Code 2.1.248–2.1.251: sandbox hardening, a lockdown flag, and an hourly cache-miss fix

TL;DR
  1. 2.1.251 is mostly a security patch round: symlink TOCTOU in file tools, plugin path traversal, and sandboxed Bash output files all get closed off, plus new approval gates on custom headers and gateway-adjacent settings.
  2. 2.1.248 adds --restricted for locking a session down to file-only tools, per-agent prompt-cache TTLs, and stops uploading uncommitted secrets (.env, .tfvars, key backups) to /ultrareview and cloud sessions.
  3. 2.1.250 shipped no user-facing changes — changelog just says 'Bug fixes and reliability improvements.'
01

Sandboxed Bash can no longer swap its own output file

If you rely on the sandbox as an actual trust boundary rather than a suggestion, this closes a redirect/replace escape on command output — worth knowing if you were treating sandboxed output as untrusted-but-contained before.

Verified · quoted from the changelogChanged how Bash command output files are created and read back when commands run in the sandbox, so a sandboxed command cannot redirect or replace them

02

Symlink-swap TOCTOU in Read/Write/Edit fixed

A permission check that approves a path, followed by a symlink swap before the actual read/write, is a classic TOCTOU — this closes it for the three core file tools, relevant if agents run in directories a concurrent process can touch.

Verified · quoted from the changelogFixed file tools (Read, Write, Edit) following a symlink swapped inside the working directory after the permission check, which could read or write outside the approved location

Verifier: Cite matches changelog verbatim; describing it as a TOCTOU fix accurately characterizes the described behavior.

03

Plugin marketplace commands can't point outside the plugin dir

If you install third-party plugins from marketplaces, this is the fix that stops a malicious/misconfigured entry from referencing files outside its own directory — a path-traversal class bug, now a hard error instead of silent execution.

Verified · quoted from the changelogFixed plugin commands declared in a marketplace entry being able to point outside the plugin directory; such paths are now rejected with a path-traversal error

Verifier: Cite matches changelog verbatim; claim accurately describes the path-traversal fix for marketplace plugin commands.

07

--restricted flag locks a session to file tools only

First real one-flag way to run an agent with no Bash/code-exec/WebFetch and no bypass-permissions escape hatch — the obvious choice for running an untrusted prompt or a CI job that should only touch files.

Verified · quoted from the changelogAdded --restricted (or CLAUDE_CODE_RESTRICTED=1): removes the built-in tools that run commands or code and WebFetch (unless named in --tools), keeps file tools inside the working directory, refuses bypassPermissions, and ignores user, project and local settings files

Verifier: Cite matches changelog verbatim; claim accurately summarizes the restricted flag's effects.

Per-agent prompt-cache TTL in frontmatter

Lets a specific subagent definition opt into a 5m or 1h cache TTL without touching global subagent TTL settings — relevant if some of your agents are long-running and others are short, bursty calls that shouldn't hold a 1h cache.

Verified · quoted from the changelogAdded experimental.cacheTtl ("5m" or "1h") to agent frontmatter: a per-agent prompt cache TTL used when no subagent TTL setting is configured
